## 3. 저장 및 데이터 규칙

데이터는 이 브라우저의 `localStorage` 키 `book-kansyo-v1`에 저장된다. 브라우저 사이트별 저장 용량(보통 약 5MB)을 따른다. 다른 브라우저, 다른 폰과는 공유되지 않는다.

### 책의 식별
- **책 = 제목 + 저자.** 앞뒤 공백만 빼고 둘 다 같아야 같은 책이다. 제목만 같거나 저자만 같으면 다른 책이다.
- **제목은 필수다.** 제목이 비면 저장되지 않는다. 예전의 `제목 없음` 자동 생성은 폐지했다.
  - `addQuote`는 제목이 비면 `throw`한다.
  - `updateBook`은 제목이 비면 `{ ok: false, error: '제목을 입력하세요.' }`를 돌려준다.
  - 화면에서는 두 곳 모두 제목이 비면 저장 버튼이 `disabled`라서 애초에 눌리지 않는다.

### 책과 문구의 독립성
- **책은 자동으로 삭제되지 않는다.** 문구를 모두 지워 0개가 되어도 책은 빈 폴더로 남는다. 코드 어디에도 "문구가 없는 책을 걸러내는" 로직이 없다.
- **책 삭제는 수동으로만.** 책 화면(`/book/:id`)의 '책 삭제'를 눌러 `window.confirm`에 동의할 때만 `deleteBook`이 돌고, 그 책과 소속 문구가 함께 지워진다.
- **문구 삭제도 수동으로만.** 문구 카드의 '삭제' → `window.confirm` → `deleteQuote`.

### 책 정보 수정은 병합하지 않는다
`updateBook`은 **병합하지 않는다.** 제목·저자를 다른 책과 똑같이 바꾸려 하면 저장을 막고 `{ ok: false, error: '같은 제목·저자의 책이 이미 있어요.' }`를 돌려준다. 책 화면은 그 문구를 폼 아래 `.status`에 띄우고, 입력칸을 고치면 메시지가 사라진다. 주소도 바뀌지 않는다.

> 이전 구현은 제목·저자가 겹치면 두 책을 조용히 합치고 편집 중이던 책을 삭제했다. '저장'이라는 이름으로 책 하나를 되돌릴 수 없게 없애는 동작이었고, "책은 자동 삭제되지 않는다"는 규칙과도 어긋났다. 그래서 차단으로 바꿨다. 중복 책을 합치는 기능이 필요하다면 별도의 의도적인 행위로 새로 설계한다.

### 중복 문구
같은 책 안에 공백만 다른 동일 본문이 이미 있으면 저장하지 않고 "이미 저장한 문구입니다"를 띄운다. 이때 화면은 홈에 머문다.

## 4. 붙여넣기 형식

마지막 줄만 서지 정보다.

```text
본문 문구. 여러 줄일 수 있다.
<책 제목>, 저자 - 밀리의 서재
```

정규식: `/^<(.+?)>\s*,\s*(.+?)\s*-\s*밀리의 서재$/`
파일: `src/lib/parseShare.js`

입력하는 동안 매 글자마다 파싱이 돌아 아래에 미리보기(제목·저자·본문 입력칸)가 펼쳐진다.

- 마지막 줄이 이 형식이면 제목·저자를 채우고 "책과 저자를 찾았습니다"를 띄운다.
- 형식이 아니면 전체를 본문으로 두고 **제목과 저자를 빈 문자열로 둔다.** "형식을 못 찾았습니다. 제목을 입력해야 저장할 수 있습니다"를 띄우고, 제목을 채울 때까지 저장 버튼이 `disabled`다.
- 저자가 여러 명이면 저자 문자열을 통째로 저장한다.
- 저장에 성공하면 입력칸이 비워지고 **곧바로 그 책 상세로 이동**한다.

## 5. 드래그 — 같은 책 안에서 순서만

책 화면(`/book/:id`)에서 문구 카드 우하단 **⋮⋮** 손잡이를 잡아 위아래로 끌어 순서를 바꾼다. 끌리는 카드는 `opacity: 0.55`가 된다. 놓으면 `reorderQuotes(bookId, orderedIds)`가 그 책 문구의 `position`을 0부터 다시 매긴다.

시작 조건이 입력 수단마다 다르다(2026-10-08 변경).

| | 센서 | 시작 조건 |
|---|---|---|
| 마우스 | `MouseSensor` | 6px 이상 움직이면 바로 |
| 손가락 | `TouchSensor` | **0.2초 길게 누르면.** 그 사이 8px 넘게 움직이면 포기하고 스크롤 |

전에는 `PointerSensor` 하나로 둘을 같이 처리해서, 휴대폰에서 손잡이를 스치며 스크롤하면 카드가 딸려 올라왔다.

- 손잡이는 책 화면에만 있다. 홈의 최근 문구와 검색 결과에는 없다.
- 손잡이는 `touch-action: manipulation`이다. **`none`이 아니다.** `none`이면 손잡이 위에서 브라우저가 스크롤을 거부해서 0.2초 지연이 무의미해진다. 카드 본문은 원래부터 제한이 없어 어디서든 정상 스크롤된다.
- 충돌 판정은 `closestCenter` 하나만 쓴다.
- 구현: `src/components/SortableQuotes.jsx` (`@dnd-kit`)

### 상태 관리
`src/lib/storage.js`가 모듈 전역 `snapshot` 하나를 들고 있다. 모든 변경은 `emit()`을 통과해 (1) 스냅샷 교체 (2) `localStorage` 직렬화 (3) 리스너 통지를 한다. 화면은 `useLibrary()`로 구독만 하고, 값은 `listBooks()` 같은 함수를 렌더 중에 직접 호출해서 쓴다.

`emit`은 `localStorage.setItem` 실패(용량 초과 등)를 잡지 않는다. 한도를 넘으면 예외가 그대로 올라온다.

### 데이터 스키마
- **책 (`books`)**: `id`, `title`, `author`, `created_at`
- **문구 (`quotes`)**: `id`, `book_id`, `text`, `page`, `note`, `raw`, `position`, `created_at`

`id`는 `crypto.randomUUID()`다. 책 목록은 `created_at` 내림차순, 책 안의 문구는 `position` 오름차순(`position`이 없으면 `created_at`)이다.

### `src/lib/storage.js` 함수
| 함수 | 하는 일 |
|---|---|
| `addQuote({title, author, text, raw})` | 제목+저자가 같은 책을 찾거나 새로 만들고 문구를 맨 뒤에 추가. 제목이 비면 `throw`. 같은 본문이 있으면 `{duplicate: true}` |
| `updateQuote(id, patch)` | `page`, `note`, `text` 중 넘어온 것만 수정 |
| `deleteQuote(id)` | 문구 1건 삭제. 책은 그대로 남음 |
| `reorderQuotes(bookId, orderedIds)` | 그 책 문구의 `position`을 0부터 재부여 |
| `updateBook(id, {title, author})` | 제목·저자 수정. `{ok}` 또는 `{ok:false, error}`. **병합하지 않음** |
| `deleteBook(id)` | 책과 소속 문구를 함께 삭제. 수동 호출만 |
| `listBooks()` | 책 목록 + `quoteCount`, 최신순 |
| `getBook(id)` / `listQuotesByBook(id)` / `listRecentQuotes(limit=5)` | 조회 |
| `searchQuotes(query)` | 본문·메모·제목·저자 부분일치, 최신순 |
| `exportJson()` | 백업 파일 생성 |
| `importJson(json)` | **덮어쓰기 복원.** 지금 데이터를 통째로 버린다 |
| `mergeJson(json)` | **합치기.** 없는 것만 더하고 겹치면 이 기기 것을 남긴다. `{books, quotes, skipped}` 반환 |
| `mockIsActive` / `loadMock` / `clearLibrary` / `ensureDragMock` | 목업. 제거 대상 |

### 문구 카드 동작 (3개 화면 공통)
페이지·메모 입력은 **포커스가 빠질 때**(`onBlur`) 값이 바뀌었을 때만 저장된다. 저장됐다는 표시는 없다. 본문(`text`)을 고치는 UI는 없다 — `updateQuote`는 지원하지만 화면에 붙어 있지 않다. 날짜는 `10월 8일 오전 10:40` 형식이다.

## 9. 이력: 드래그 무반응 (2026-10-07 해결, 2026-10-08 무효화)

자세한 분석: `doc/드래그-무반응-원인분석.md`

`.move-tray`의 `position: sticky; bottom: 0` 때문에 책이 많아지면 트레이가 화면보다 커지면서 문구 목록을 덮었고, 포인터가 손잡이에 닿지 못했다. dnd-kit 설정은 처음부터 정상이었다. `sticky`를 제거해 해결했고, `setActivatorNodeRef`를 손잡이 버튼에 연결하는 개선을 함께 넣었다.

**지금은 트레이 자체가 없다.** 2026-10-08에 "다른 책으로 묶기"를 제거하면서 `.move-tray`를 비롯한 관련 CSS와 컴포넌트가 모두 사라졌으므로, 그 문서는 **과거 기록**으로만 유효하다. 다만 거기 적힌 교훈은 살아 있다.

- `position: sticky`는 그 요소가 화면보다 커지는 경우를 반드시 생각한다. 개수가 늘어나는 목록이면 특히 그렇다.
- "클릭·드래그가 안 된다"는 핸들러 문제처럼 보이지만 무언가 위를 덮은 경우가 흔하다. `document.elementFromPoint(손잡이 좌표)`로 1분이면 가린다.
- 겹침 버그를 "조금만 겹치게" 줄이는 식으로 타협하면 더 찾기 어려워진다. 겹침 자체를 없앤다.

유지되고 있는 구현 사항:
- `setActivatorNodeRef`를 손잡이 버튼에 연결 (`SortableQuotes.jsx` → `QuoteItem.jsx`)
- 손잡이의 `touch-action` (단, `none` → `manipulation`으로 바뀌었다. 위 5장을 본다)

### 헷갈리기 쉬운 것
`.move-target`이 사라졌으므로 **드롭 대상 강조는 더 이상 없다.** 지금 드래그 중 보이는 변화는 끌리는 카드의 `opacity: 0.55`와 다른 카드가 밀려나는 애니메이션뿐이다.
