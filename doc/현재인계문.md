## 3. PWA와 공유 메뉴

개념 설명은 `doc/공유메뉴-등록-설명.md`에 따로 있다. 여기서는 구현 사실만 적는다.

### 구성 파일

| 파일 | 역할 |
|---|---|
| `public/manifest.webmanifest` | 앱 신고서 + `share_target` + 바로가기 |
| `public/sw.js` | 서비스 워커. 설치 조건 충족 + 오프라인 |
| `public/app-icon.svg` | 탭 아이콘 |
| `public/icon-192.png`, `icon-512.png` | 홈 화면·설치 |
| `public/icon-maskable-512.png` | 안드로이드가 아이콘을 잘라낼 때 |
| `index.html` | manifest·아이콘 연결, `theme-color`, `viewport-fit=cover` |
| `src/main.jsx` | 서비스 워커 등록 (`import.meta.env.PROD`일 때만) |

`public/favicon.svg`, `public/icons.svg`는 Vite 템플릿 잔재다. 아무도 참조하지 않는다.

### 공유가 들어오는 길

```
밀리의 서재 → 안드로이드 공유 메뉴 → "북칸쇼"
→ GET /share?title=&text=&url=
→ src/pages/Share.jsx        주소에서 꺼냄
→ src/lib/shareTarget.js     셋을 한 덩어리로 합침
→ src/lib/parseShare.js      제목·저자·본문으로 쪼갬  ← 기존 코드 그대로
→ PasteBox (initialRaw)      채워진 채로 열림
```

**붙여넣기 경로와 저장 로직은 손대지 않았다.** 입구만 하나 더 뚫은 구조다.
`PasteBox`에 `initialRaw`와 `label` prop이 추가된 것이 전부다.

`method`는 `GET`이다. 글자만 받으므로 서비스 워커가 요청을 가로챌 필요가 없다.
사진을 받으려면 `POST`로 바꾸고 서비스 워커에서 처리해야 한다.

### 서비스 워커 동작

- 화면 이동: 네트워크 먼저, 실패하면 캐시한 `/index.html`
- 그 외 같은 출처 GET: 캐시 있으면 캐시, 없으면 받아서 저장
- 캐시 이름 `book-kansyo-v1`. `sw.js`를 고치면 **이 이름도 올려야** 옛 캐시가 정리된다

### 배포 전 반드시 할 것

**SPA 폴백.** `/share`를 포함한 모든 경로가 `index.html`을 받아야 한다.
없으면 공유 메뉴에서 골랐을 때 404가 난다.

```
Netlify  → public/_redirects:  /*  /index.html  200
Vercel   → vercel.json 의 rewrites
nginx    → try_files $uri $uri/ /index.html;
```

지금까지 이게 없어도 됐던 건 늘 `/`로 들어가 앱 안에서만 이동했기 때문이다.
공유는 `/share`로 **바로** 들어오므로 여기서 처음 문제가 된다.

그리고 **HTTPS여야** 한다. 설치가 안 되면 공유 메뉴에도 뜨지 않는다.

## 4. 데이터 안전 — 서버가 없으므로 백업이 유일한 안전망

### 네 조각

| 파일 | 하는 일 |
|---|---|
| `src/lib/persist.js` | `navigator.storage.persist()`로 저장소를 지우지 말라고 요청 |
| `src/lib/backup.js` | 마지막 백업 시점·문구 수 기록, 알림 판단, 내보내기 |
| `src/lib/storage.js` | `setItem` 실패를 잡아 `getWriteError()`로 알림 |
| `src/components/StorageNotice.jsx` | 위 셋을 배너 하나로. `App.jsx`에서 모든 화면 위에 |

### persist 요청 시점

**저장할 문구가 생겼을 때만** 자동으로 부른다(`hasData`). 파이어폭스가 이 요청에
권한 창을 띄우기 때문에, 빈 앱에서 먼저 묻지 않게 했다. 거절되면 배너에 버튼이 남는다.
목업만 있을 때는 요청하지 않는다.

### 백업 알림 규칙

`src/lib/backup.js`의 `evaluateReminder`. **순수 함수라 테스트로 덮여 있다**(`backup.test.js`).

```
문구 0개              → 안 함
"나중에" 누른 지 3일 안 → 안 함
백업한 적 없음         → 권함
백업 후 새 문구 0개    → 안 함
새 문구 있고 7일 경과   → 권함
새 문구 20개 이상      → 기간 무관하게 권함
목업이 켜져 있음       → 안 함
```

상태 키: `book-kansyo-backup-v1` (`{at, count, snoozedAt}`).
내보내기·가져오기를 하면 `markBackupDone()`이 돌아 알림이 꺼진다.

### 쓰기 실패

`emit`의 `localStorage.setItem`을 `try/catch`로 감쌌다. 사파리 비공개 모드나 용량 초과에도
**화면은 그대로 돌아가고** 배너가 "지금 내보내세요"라고 알린다.
(이전 판 인계문의 "emit은 실패를 잡지 않는다"는 더 이상 사실이 아니다.)

## 5. 기기 간 이동 — 자동 동기화는 없다

데이터는 각 기기의 `localStorage`에만 있다. **크롬 동기화는 `localStorage`를 옮기지 않는다.**
같은 구글 계정이어도 폰과 맥은 서로 다른 데이터를 본다.

```
윈도 PC 크롬  │  맥북 크롬  │  안드로이드 폰 크롬
     ↑ 셋이 각자 따로. 다리는 JSON 파일 하나뿐
```

### 두 가지 가져오기

| 버튼 | 함수 | 하는 일 |
|---|---|---|
| **합치기 가져오기** | `mergeJson` | 없는 것만 더한다. 평소 쓰는 것 |
| 덮어쓰기 복원… | `importJson` | 통째로 갈아끼운다. 기기 교체·데이터 손상용 |

덮어쓰기는 `text-button`으로 눈에 덜 띄게 두고, 누르면 **지워질 문구 개수를 보여주고
한 번 더 묻는다**(`BackupBox.jsx`의 `askReplace`).

### 합치는 규칙

```
책:   id가 같으면 → 같은 책
      제목·저자가 같으면 → 같은 책      ← 이게 없으면 책이 둘로 갈라진다
      아니면 → 새 책
문구: id가 겹치거나 같은 책에 같은 본문이 있으면 → 건너뜀
      아니면 → 그 책 맨 뒤에 붙임 (position 이어서 부여)
```

`id`는 기기마다 따로 만들어지므로(`crypto.randomUUID`), 같은 책을 두 기기에서
저장했으면 id가 다르다. 그래서 제목·저자로도 맞춰 본다.
**겹칠 때는 언제나 이 기기 것을 남긴다.** 저쪽 메모가 이쪽을 덮지 않는다.

규칙별 테스트는 `src/lib/storage.test.js`의 `mergeJson` describe 블록에 있다.

### 알고 넘어간 한계

- **삭제는 전파되지 않는다.** 폰에서 지운 문구가 맥에서 합치기하면 되살아난다.
  합치기는 "없는 것을 더하는" 동작이기 때문이다.
  → **지우기는 주 기기에서만 한다**는 운용으로 넘겼다.
- **순서는 가져오는 쪽 기준.** 합쳐 들어온 문구는 책 맨 뒤로 간다.
- 합치기는 **되돌릴 수 없다.** 합치기 전에 내보내기를 먼저 한다.

제대로 풀려면 `deleted_at`(soft delete)과 `updated_at`이 필요하다.
`doc/데이터-보관-결정.md` 5장에 적어 뒀다.

## 6. 저장 및 데이터 규칙

데이터는 `localStorage` 키 `book-kansyo-v1`. 브라우저 사이트별 용량(보통 약 5MB)을 따른다.

### 책의 식별
- **책 = 제목 + 저자.** 앞뒤 공백만 빼고 둘 다 같아야 같은 책이다.
- **제목은 필수다.** 비면 저장되지 않는다. 예전의 `제목 없음` 자동 생성은 폐지했다.
  - `addQuote`는 제목이 비면 `throw`
  - `updateBook`은 `{ ok: false, error: '제목을 입력하세요.' }`
  - 화면에서는 둘 다 저장 버튼이 `disabled`라 애초에 눌리지 않는다

### 책과 문구의 독립성
- **책은 자동으로 삭제되지 않는다.** 문구가 0개가 되어도 빈 폴더로 남는다.
- **책 삭제는 수동으로만.** `/book/:id`의 '책 삭제' → `window.confirm` → 책과 소속 문구 함께.
- **문구 삭제도 수동으로만.** 카드의 '삭제' → `window.confirm`.

### 책 정보 수정은 병합하지 않는다
`updateBook`은 제목·저자를 다른 책과 똑같이 바꾸려 하면 **막는다.**
`{ ok: false, error: '같은 제목·저자의 책이 이미 있어요.' }`

> 이전 구현은 겹치면 두 책을 조용히 합치고 편집 중이던 책을 삭제했다.
> '저장'이라는 이름으로 책 하나를 되돌릴 수 없게 없애는 동작이었다.
> 합치기가 필요하면 별도의 의도적인 행위로 새로 설계한다.

### 중복 문구
같은 책 안에 공백만 다른 동일 본문이 있으면 저장하지 않고 "이미 저장한 문구입니다"를 띄운다.

## 7. 붙여넣기 형식

마지막 줄만 서지 정보다.

```text
본문 문구. 여러 줄일 수 있다.
<책 제목>, 저자 - 밀리의 서재
```

정규식 `/^<(.+?)>\s*,\s*(.+?)\s*-\s*밀리의 서재$/` · `src/lib/parseShare.js`

입력하는 동안 매 글자마다 파싱이 돌아 미리보기가 펼쳐진다.

- 형식이면 제목·저자를 채우고 "책과 저자를 찾았습니다"
- 아니면 전체를 본문으로 두고 제목·저자는 빈 문자열. 제목을 채울 때까지 저장 `disabled`
- 저자가 여러 명이면 문자열 통째로 저장
- 저장 성공 시 입력칸이 비워지고 **곧바로 그 책 상세로 이동**

공유로 들어온 경우 `initialRaw`로 같은 파싱이 처음부터 돌아 있다.

## 8. 드래그 — 같은 책 안에서 순서만

**⋮⋮** 손잡이를 잡아 위아래로 끈다. 끌리는 카드는 `opacity: 0.55`.
놓으면 `reorderQuotes(bookId, orderedIds)`가 `position`을 0부터 다시 매긴다.

시작 조건이 입력 수단마다 다르다(2026-10-08 변경).

| | 센서 | 시작 조건 |
|---|---|---|
| 마우스 | `MouseSensor` | 6px 이상 움직이면 바로 |
| 손가락 | `TouchSensor` | **0.2초 길게 누르면.** 그 사이 8px 넘게 움직이면 포기하고 스크롤 |

전에는 `PointerSensor` 하나로 둘을 같이 처리해서, 폰에서 손잡이를 스치며 스크롤하면
카드가 딸려 올라왔다.

- **손잡이는 `touch-action: manipulation`이다. `none`이 아니다.**
  `none`이면 손잡이 위에서 브라우저가 스크롤을 거부해 0.2초 지연이 무의미해진다.
  **센서와 CSS는 짝이다.** 센서를 되돌리면 CSS도 같이 되돌려야 한다.
- 손잡이는 책 화면에만 있다. 홈·검색에는 없다.

### 상태 관리

`storage.js`가 모듈 전역 `snapshot` 하나를 들고 있다. 모든 변경은 `emit()`을 통과해
(1) 스냅샷 교체 (2) `localStorage` 직렬화(실패 시 `writeError` 기록) (3) 리스너 통지.
화면은 `useLibrary()`로 구독만 하고, 값은 `listBooks()` 같은 함수를 **렌더 중에 직접** 호출한다.

> 이 구조 덕분에 화면 컴포넌트가 `storage.js` 하나만 통한다.
> 나중에 서버를 붙이게 되면 바꿀 곳이 사실상 이 파일 하나다.

### 데이터 스키마

- **책**: `id`, `title`, `author`, `created_at`
- **문구**: `id`, `book_id`, `text`, `page`, `note`, `raw`, `position`, `created_at`

`id`는 `crypto.randomUUID()`. 책 목록은 `created_at` 내림차순,
책 안의 문구는 `position` 오름차순(없으면 `created_at`).

### localStorage 키

| 키 | 내용 |
|---|---|
| `book-kansyo-v1` | 본 데이터 `{books, quotes}` |
| `book-kansyo-mock-v1` | 목업 플래그 `1` / `off` |
| `book-kansyo-backup-v1` | 백업 상태 `{at, count, snoozedAt}` |

### `src/lib/storage.js` 함수

| 함수 | 하는 일 |
|---|---|
| `addQuote({title, author, text, raw})` | 책을 찾거나 만들고 문구를 맨 뒤에. 제목 비면 `throw`. 중복이면 `{duplicate:true}` |
| `updateQuote(id, patch)` | `page`, `note`, `text` 중 넘어온 것만 |
| `deleteQuote(id)` / `deleteBook(id)` | 삭제. 책 삭제는 소속 문구까지 |
| `reorderQuotes(bookId, orderedIds)` | `position` 재부여 |
| `updateBook(id, {title, author})` | `{ok}` 또는 `{ok:false, error}`. **병합 안 함** |
| `listBooks()` / `getBook` / `listQuotesByBook` / `listRecentQuotes` | 조회 |
| `searchQuotes(query)` | 본문·메모·제목·저자 부분일치, 최신순 |
| `exportJson()` | 백업 문자열 |
| `importJson(json)` | **덮어쓰기.** 지금 데이터를 버린다 |
| `mergeJson(json)` | **합치기.** `{books, quotes, skipped}` 반환 |
| `getWriteError()` | 저장 실패 메시지 또는 `''` |
| `mockIsActive` / `loadMock` / `clearLibrary` / `ensureDragMock` | 목업. 제거 대상 |

### 문구 카드 동작 (3개 화면 공통)

페이지·메모는 **포커스가 빠질 때**(`onBlur`) 값이 바뀌었을 때만 저장된다. 저장 표시는 없다.
본문(`text`)을 고치는 UI는 없다 — `updateQuote`는 지원하지만 화면에 붙어 있지 않다.
날짜는 `10월 8일 오전 10:40` 형식.

## 12. 이력: 드래그 무반응 (2026-10-07 해결, 2026-10-08 무효화)

자세한 분석: `doc/드래그-무반응-원인분석.md`

`.move-tray`의 `position: sticky; bottom: 0` 때문에 책이 많아지면 트레이가 화면보다 커지며
문구 목록을 덮었고, 포인터가 손잡이에 닿지 못했다. dnd-kit 설정은 처음부터 정상이었다.

**지금은 트레이 자체가 없다.** 그 문서는 과거 기록으로만 유효하다. 다만 교훈은 살아 있다.

- `position: sticky`는 그 요소가 화면보다 커지는 경우를 반드시 생각한다
- "클릭·드래그가 안 된다"는 핸들러 문제처럼 보이지만 무언가 위를 덮은 경우가 흔하다.
  `document.elementFromPoint(손잡이 좌표)`로 1분이면 가린다
- 겹침을 "조금만 겹치게" 줄이는 식으로 타협하면 더 찾기 어려워진다. 겹침 자체를 없앤다

유지되고 있는 구현:
- `setActivatorNodeRef`를 손잡이 버튼에 연결 (`SortableQuotes.jsx` → `QuoteItem.jsx`)
- 손잡이의 `touch-action` (단 `none` → `manipulation`으로 바뀌었다. 8장)

### 헷갈리기 쉬운 것

`.move-target`이 사라졌으므로 **드롭 대상 강조는 없다.** 드래그 중 보이는 변화는
끌리는 카드의 `opacity: 0.55`와 다른 카드가 밀려나는 애니메이션뿐이다.
