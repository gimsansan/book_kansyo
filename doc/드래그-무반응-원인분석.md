# 드래그 무반응 원인 분석

작성일: 2026-10-07
대상: 책 화면(`/book/:id`)의 문구 드래그

> **2026-10-08 기준: 이 문서는 과거 기록이다.**
> 여기서 다루는 "다른 책으로 묶기" 트레이(`.move-tray`)는 2026-10-08에 기능째로 제거됐다.
> `.move-tray` / `.move-list` / `.move-target` CSS와 `BookDrop` 컴포넌트, `moveQuoteToBook`이
> 모두 코드에 없으므로, 아래의 증상·조치는 더 이상 재현되지 않는다.
> 지금 남아 있는 것은 `setActivatorNodeRef` 연결과 손잡이의 `touch-action: none`,
> 그리고 7장의 교훈뿐이다. 현재 동작은 `doc/현재인계문.md` 5장과 9장을 본다.

## 1. 증상

- **⋮⋮** 손잡이를 끌어도 문구 카드가 흐려지지 않았다. 드래그가 시작조차 안 됐다.
- "다른 책으로 묶기"의 책 카드 위로 가져가도 테두리·배경 강조(`.over`)가 안 떴다.
- 마우스와 손가락 모두 반응이 없었다.

---

## 2. 원인

`src/index.css`의 `.move-tray`가 이렇게 돼 있었다.

```css
.move-tray {
  position: sticky;
  bottom: 0;
  background: color-mix(in srgb, var(--paper) 94%, transparent);
}
```

`position: sticky; bottom: 0`은 "요소의 아래끝을 화면 아래끝에 붙여 둔다"는 뜻이다.
그런데 목업에 책이 9권이라 트레이 높이가 약 550px가 됐고, 화면 높이는 525px였다.
**요소가 화면보다 크면** sticky가 요소를 위로 끌어올려 아래끝을 맞춘다.
그 결과 트레이가 문구 목록 위까지 올라와 화면 전체를 덮었다.

덮은 것으로 끝이 아니다. 트레이에는

- 불투명한 `background`가 있고
- `position`이 붙어 있어 일반 요소보다 **위 레이어**에 그려진다

그래서 손잡이는 시각적으로도 가려지고, 포인터 이벤트도 트레이가 먼저 가로챘다.
손잡이의 `onPointerDown`은 한 번도 불리지 않았다.

> dnd-kit 설정(센서, 리스너, 충돌 판정)은 처음부터 정상이었다. CSS 레이아웃 문제였다.

## 3. 분석 과정

### 3-1. 리스너가 붙어 있는지 확인

브라우저에서 손잡이 DOM의 React props를 직접 읽었다.

```js
const h = document.querySelector('.drag-handle')
Object.keys(h[Object.keys(h).find((k) => k.startsWith('__reactProps'))])
// → [..., 'onPointerDown', 'aria-roledescription', 'aria-describedby', ...]
```

`onPointerDown`과 dnd-kit의 aria 속성이 모두 붙어 있었다.
**리스너 문제는 아니다.**

### 3-2. 포인터가 손잡이에 닿는지 확인 (결정적 단서)

손잡이 좌표를 `elementFromPoint`로 되짚었다.

```js
const r = h.getBoundingClientRect()
document.elementFromPoint(r.x + r.width / 2, r.y + r.height / 2)
// → <strong> (= .move-target 안의 책 제목)
```

손잡이 자기 좌표인데 손잡이가 안 잡혔다. **무언가 위를 덮고 있다.**

### 3-3. 모든 스크롤 위치에서 반복

```js
for (let y = 0; y <= document.documentElement.scrollHeight; y += 100) {
  window.scrollTo(0, y)
  // 손잡이 중심 좌표에서 elementFromPoint 확인
}
```

결과: **어느 스크롤 위치에서도** 손잡이가 잡히지 않았다. 항상 화면 밖이거나 `.move-target`이었다.

### 3-4. 반대로 증명

sticky만 임시로 끄고 같은 검사를 했다.

```js
document.head.insertAdjacentHTML(
  'beforeend',
  '<style>.move-tray{position:static !important}</style>',
)
// → elementFromPoint가 BUTTON.drag-handle 반환
```

그리고 포인터 이벤트를 흉내 내 끌어 봤더니

- 카드 `opacity: 0.55` (드래그 시작됨)
- `.move-target.over` 1개 (드롭 대상 인식됨)
- 놓으니 문구가 실제로 다른 책으로 이동

**dnd-kit은 멀쩡하다. 범인은 sticky 트레이로 확정.**

## 4. 해결

### 4-1. 먼저 시도했다가 버린 안: 높이만 줄이기

```css
.move-tray {
  position: sticky;
  bottom: 0;
  max-height: 40vh; /* 화면의 40%만 덮게 */
}
```

손잡이를 집는 것까지는 됐다. 하지만 **순서 바꾸기가 깨졌다.**
첫 문구를 끌어 두 번째 문구에 놓으려는데, 두 번째 문구가 트레이 40% 영역 뒤에 숨어 있었다.
dnd-kit은 포인터 위치로 드롭 대상을 고르므로, "순서 바꾸기"가 "다른 책으로 옮기기"로 잘못 처리됐다.

**조금이라도 겹치면 같은 종류의 버그가 남는다.** 그래서 버렸다.

### 4-2. 채택한 안: 겹침을 아예 없애기

`src/index.css`

```css
/* sticky로 띄우면 문구 위를 덮어 드래그 손잡이를 집을 수 없다 */
.move-tray {
  display: grid;
  gap: 0.45rem;
  padding: 0.7rem 0 0.2rem;
  background: color-mix(in srgb, var(--paper) 94%, transparent);
}
```

트레이는 문구 목록 아래 보통 흐름에 놓인다. 아무것도 덮지 않는다.
끌어서 아래로 내려가면 dnd-kit 자동 스크롤이 따라 내려가므로 사용성 손해는 거의 없다.

### 4-3. 같이 고친 것: `setActivatorNodeRef`

`src/components/SortableQuotes.jsx`

```jsx
const { attributes, listeners, setNodeRef, setActivatorNodeRef, ... } =
  useSortable({ id: quote.id })

<QuoteItem dragHandle={{ attributes, listeners, setActivatorNodeRef }} />
```

`src/components/QuoteItem.jsx`

```jsx
const setHandleRef = dragHandle?.setActivatorNodeRef
// ...
<button ref={setHandleRef} className="drag-handle" ...>⋮⋮</button>
```

dnd-kit이 권하는 방식이다. 드래그를 **시작시키는 요소**가 손잡이 버튼임을 알려 줘서,
키보드 드래그와 접근성 속성이 카드 전체가 아니라 손잡이 기준으로 맞춰진다.

## 6. 쉬운 비유로 보는 전말

### 상황

**책상 위에 서류(문구 카드)를 올려 두고, 서류 왼쪽 귀퉁이의 작은 손잡이를 잡아 옮기는 작업**이라고 하자.
책상 앞쪽에는 "이 서류를 넣을 서랍 목록"을 적은 **안내판**이 세워져 있다. (= 다른 책으로 묶기 트레이)

### 원인

안내판을 "항상 눈앞에 보이게" 하려고 **유리창에 붙여 뒀다.** (= `position: sticky`)

처음엔 서랍이 2~3개라 안내판이 작아서 괜찮았다.
그런데 서랍이 9개로 늘자 안내판이 **유리창보다 커졌다.**
아래끝을 창 아래에 맞추려다 보니 안내판이 위로 밀려 올라가 **창 전체를 가려 버렸다.**

이제 당신은 서류를 볼 수도 없고, 손을 뻗어도 **안내판에 막힌다.**
서류의 손잡이는 멀쩡히 거기 있는데, 손이 닿지를 않는다.

### 그래서 오해했던 것

밖에서 보면 "손잡이가 고장 났다"로 보인다.
그래서 처음엔 손잡이(dnd-kit 설정)를 의심했다. 글꼴 탓, 센서 탓, React 탓을 차례로 뒤졌다.
**손잡이는 멀쩡했다. 손이 닿지 않았을 뿐이다.**

### 어떻게 알아냈나

"손잡이가 있는 자리를 손가락으로 찍으면, 실제로 뭐가 만져지나?"를 물었다. (= `elementFromPoint`)
답은 **안내판**이었다. 그걸로 끝났다.

안내판을 잠깐 치우고 다시 찍어 보니 손잡이가 만져졌고, 끌어 보니 잘 됐다.
**범인 확정.**

### 왜 "안내판을 작게 만들기"로는 부족했나

안내판을 창의 40% 크기로 줄여 봤다.
서류는 보인다. 그런데 **서류 두 장을 서로 바꾸려니, 두 번째 장이 안내판 뒤에 숨어 있었다.**
거기에 내려놓으면 "자리 바꾸기"가 아니라 "서랍에 넣기"가 돼 버린다.

조금이라도 가리면 같은 사고가 난다.

### 최종 해결

**안내판을 유리창에서 떼어 책상 위, 서류 아래쪽에 그냥 세워 뒀다.** (= sticky 제거)
이제 아무것도 가리지 않는다.
서류를 끌고 아래로 내려가면 책상이 알아서 따라 움직인다. (= dnd-kit 자동 스크롤)

그리고 "이 서류를 옮기는 손잡이는 바로 이 귀퉁이다"라고 **이름표를 붙여 뒀다.**
(= `setActivatorNodeRef`)

## 7. 교훈

- `position: sticky`를 쓸 때는 **그 요소가 화면보다 커지는 경우**를 반드시 생각한다. 목록처럼 개수가 늘어나는 요소라면 특히 그렇다.
- "클릭/드래그가 안 된다"는 이벤트 핸들러 문제처럼 보이지만, **무언가 위를 덮고 있는 경우**가 흔하다. `document.elementFromPoint`로 1분이면 가린다.
- 겹침 버그는 "조금만 겹치게" 줄이는 식으로 타협하면 더 찾기 어려운 형태로 남는다. 가능하면 **겹침 자체를 없앤다.**

**오해.** 밖에서 보면 "손잡이가 고장 났다"로 보입니다. 그래서 처음엔 손잡이 자체, 즉 dnd-kit 설정을 의심하게 됩니다. 글꼴 탓, 센서 탓, React 탓을 차례로 뒤지게 되죠.
