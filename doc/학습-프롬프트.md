작성일: 2026-10-08

관련 문서: `doc/공유메뉴-등록-설명.md` (무엇을 했는지), 이 문서 (그 밑의 개념을 배우기)

## ① 공통 머리말 — 대화 맨 처음에 한 번

```
나는 웹 개발 기초가 부족한 상태로 React + Vite로 개인 앱을 만들고 있어.
"북칸쇼"라는 독서 노트 앱이고, 전자책 앱(밀리의 서재)에서 공유한 문구를
책별로 모아 두는 용도야. 데이터는 아직 브라우저 localStorage에만 있어.

방금 이 앱을 PWA로 바꿔서 "안드로이드 공유 메뉴에 앱이 뜨게" 하는 작업을 했는데,
코드는 돌아가지만 내가 개념을 이해하지 못한 상태야. 지금부터 그 밑에 깔린
개념들을 하나씩 물어볼 거야.

답할 때 지켜줬으면 하는 것:
- 전문 용어는 처음 나올 때 한 번은 일상적인 비유로 풀어줘.
- "이건 원래 어떤 문제를 풀려고 생긴 건가"를 먼저 말하고 나서 동작을 설명해줘.
- 가능하면 ASCII 그림이나 표로 흐름을 보여줘.
- 초보가 흔히 오해하는 지점을 따로 짚어줘.
- 설명 끝에 내가 이해했는지 확인할 질문 2개를 던져줘. 내가 답하면 채점해줘.
- 길이는 한 번에 소화 가능한 정도로. 너무 길면 끊어서 "더 볼래?" 하고 물어봐.

준비됐으면 "시작" 이라고만 답해줘.
```

## ② 웹앱 / 네이티브 앱 / PWA — 가장 먼저

```
"PWA(Progressive Web App)"가 뭔지 설명해줘. 특히 이것들을 구분해서 알고 싶어:

- 그냥 웹사이트, PWA, 네이티브 앱(플레이스토어에서 받는 것) 셋의 차이
- "앱을 설치한다"는 게 웹에서는 정확히 무슨 일이 일어나는 건지
  (뭐가 어디에 저장되는 건지, 플레이스토어 앱 설치와 뭐가 다른지)
- 홈 화면에 추가한 PWA가 할 수 있는 것과 끝내 못 하는 것
- PWA가 왜 생겼는지, 어떤 상황에서 쓸만하고 어떤 상황에서는 네이티브가 나은지

나는 개인용 독서 노트 앱을 만들고 있고, 사용자는 나 혼자야.
이 상황에서 PWA를 고른 게 합리적인지도 평가해줘.
```

## ③ manifest와 "설치 조건"

```
PWA의 manifest 파일(web app manifest)에 대해 알려줘.

- manifest가 없으면 뭐가 안 되는지
- 주요 항목들이 각각 뭘 결정하는지:
  name, short_name, start_url, scope, display, theme_color, background_color, icons, id
  특히 start_url과 scope의 차이, display의 standalone/browser/fullscreen 차이를
  실제 화면이 어떻게 달라지는지로 설명해줘.
- 크롬이 "이건 설치 가능한 앱이다"라고 판단하는 조건이 정확히 뭔지
  (내가 듣기로는 HTTPS, manifest, 서비스 워커 세 가지라는데 맞는지,
   최근 크롬에서 기준이 바뀐 게 있는지도 알려줘)
- manifest를 고쳤는데 폰에 반영이 안 될 때 흔한 원인

내 manifest는 이렇게 생겼어. 이상한 점이나 빠진 게 있으면 짚어줘:

{
  "id": "/",
  "name": "북칸쇼 독서 노트",
  "short_name": "북칸쇼",
  "start_url": "/",
  "scope": "/",
  "display": "standalone",
  "background_color": "#f3eee6",
  "theme_color": "#f3eee6",
  "icons": [ ... 192, 512, maskable 512 ... ]
}
```

## ④ 안드로이드 공유 시스템과 Web Share Target

```
안드로이드에서 "공유" 버튼을 눌렀을 때 뜨는 앱 목록이 어떻게 만들어지는지 알려줘.

- 안드로이드 인텐트(Intent)가 뭔지, 공유가 인텐트의 어떤 종류인지
- 앱이 저 목록에 등장하려면 뭘 등록해야 하는지 (네이티브 앱 기준으로 먼저)
- 웹 앱이 같은 목록에 끼는 방법인 Web Share Target이 뭔지,
  네이티브 앱의 등록과 어떻게 연결되는지
- Web Share(공유 "하는" 쪽)와 Web Share Target(공유 "받는" 쪽)의 차이.
  이름이 비슷해서 헷갈려.
- share_target의 params에 있는 title / text / url이 각각 뭘 담는지,
  보내는 앱마다 다르게 담아서 생기는 문제는 뭔지

내 manifest에는 이렇게 넣었어. 한 줄씩 무슨 뜻인지 풀어줘:

"share_target": {
  "action": "/share",
  "method": "GET",
  "enctype": "application/x-www-form-urlencoded",
  "params": { "title": "title", "text": "text", "url": "url" }
}
```

## ⑤ HTTP GET/POST와 쿼리스트링

```
HTTP의 GET과 POST 차이를 기초부터 알려줘. 나는 둘의 차이를 "데이터를 주소에 붙이냐,
안 붙이냐" 정도로만 어렴풋이 알고 있어.

- 요청(request)이 실제로 어떻게 생겼는지 날것 그대로 보여줘 (GET 하나, POST 하나)
- 쿼리스트링(?a=1&b=2)의 구조, URL 인코딩이 왜 필요한지
  (한글이나 줄바꿈, &, = 같은 글자를 넣으면 어떻게 되는지 예시로)
- GET에 담을 수 있는 길이 제한이 있는지
- 어떤 걸 GET으로 보내면 안 되는지 (보안·캐시·기록 관점)
- 브라우저 주소창에 뭘 치는 것은 왜 항상 GET인지

그리고 이걸 내 상황에 적용해서 판단해줘:
공유받은 문구(한글 몇 줄 + 책 제목)를 앱에 전달하는데 GET을 골랐어.
POST였다면 뭐가 달라졌을지, 사진까지 받으려면 왜 POST여야 하는지,
내 선택이 타당한지 알려줘.
```

## ⑥ SPA와 라우팅 — "서버가 /share를 모른다"

```
SPA(Single Page Application)에서 라우팅이 어떻게 동작하는지 알려줘.
이게 지금 내가 제일 안 잡히는 부분이야.

- 옛날 방식(서버가 주소마다 다른 HTML 파일을 주는 것)과
  SPA 방식(파일은 index.html 하나뿐이고 JS가 화면을 갈아끼우는 것)을
  요청이 오가는 순서대로 비교해줘.
- "클라이언트 사이드 라우팅"이 실제로 쓰는 기술이 뭔지
  (History API의 pushState 같은 것) — 주소창이 바뀌는데 왜 서버에 요청이 안 가는지
- 그런데 사용자가 /share 주소를 주소창에 직접 쳐서 들어오면 왜 서버에 요청이 가고,
  왜 404가 나는지. "주소창에 직접 입력"과 "앱 안에서 링크 클릭"이
  왜 완전히 다른 일인지 그림으로 보여줘.
- 이걸 해결하는 "SPA 폴백 / history fallback"이 서버에서 하는 일이 정확히 뭔지
- Netlify(_redirects), Vercel(vercel.json), nginx(try_files), GitHub Pages에서
  각각 어떻게 설정하는지 실제 설정 파일 내용으로 보여줘
- 개발 서버(vite dev)에서는 왜 설정 안 해도 잘 되는지

내 앱은 React Router를 쓰고 BrowserRouter를 써. HashRouter를 쓰면
이 문제가 사라진다고 들었는데, 그 대신 뭘 잃는지도 알려줘.
```

## ⑦ 서비스 워커

```
서비스 워커(Service Worker)가 뭔지 알려줘. 개념이 제일 안 잡혀.

- 원래 어떤 문제를 풀려고 만들어진 건지
- "앱과 네트워크 사이에 끼어든다"는 게 코드로는 어떤 모양인지
  (fetch 이벤트를 가로채는 것)
- 생명주기: install → activate → fetch 가 각각 언제 일어나는지,
  skipWaiting()과 clients.claim()이 왜 필요한지
- 캐시 전략 몇 가지 (cache-first / network-first / stale-while-revalidate)를
  언제 쓰는지 비교표로
- 왜 "서비스 워커를 한 번 등록하면 지우기 어렵다"는 말이 나오는지,
  옛날 파일이 계속 보이는 문제가 왜 생기고 어떻게 푸는지
- 개발 중에 서비스 워커를 끄는 게 권장되는 이유
- 서비스 워커가 할 수 없는 것 (DOM 접근 등)과 그 이유
- HTTPS에서만 되는 이유

그리고 아래가 내가 넣은 서비스 워커야. 뭘 하고 있는지 한 줄씩 해설해주고,
초보가 이 코드에서 다칠 만한 부분을 짚어줘:

(여기에 public/sw.js 내용 붙여넣기)
```

> 마지막 줄에 `public/sw.js` 파일 내용을 복사해 넣는다.

## ⑧ HTTPS와 보안 컨텍스트

```
PWA 관련 기능들이 "HTTPS에서만 동작한다"고 하는데, 그 이유를 알려줘.

- HTTP와 HTTPS의 차이를 중간에서 누가 뭘 할 수 있는지로 설명해줘
- "보안 컨텍스트(secure context)"가 뭔지, 어떤 웹 기능들이 여기 묶여 있는지
  (서비스 워커, 위치, 카메라, 클립보드 등)
- 서비스 워커를 HTTP에 허용하면 구체적으로 어떤 공격이 가능해지는지
- localhost는 왜 예외로 허용되는지
- 개인 프로젝트를 HTTPS로 배포하는 현실적인 방법들
  (Netlify, Vercel, Cloudflare Pages, GitHub Pages 비교 — 무료 범위, 난이도,
   SPA 폴백 설정 편한 정도 기준으로)
```

## ⑨ 아이콘과 maskable

```
PWA 아이콘에 대해 알려줘.

- manifest의 icons에 여러 크기를 넣는 이유, 어떤 크기가 어디에 쓰이는지
- purpose가 "any"와 "maskable"로 나뉘는 이유.
  안드로이드가 아이콘을 어떻게 가공하는지(adaptive icon) 그림으로 설명해줘
- maskable 아이콘의 "safe zone"이 뭔지, 비율이 얼마인지,
  이걸 안 지키면 실제로 어떻게 보이는지
- SVG 아이콘을 manifest에 쓸 수 있는지, 왜 보통 PNG를 쓰는지
- favicon, apple-touch-icon, manifest icons가 각각 누가 쓰는 건지 정리해줘
  (셋을 다 넣어야 하는 이유)
- 아이콘이 적용 안 될 때 캐시 때문에 생기는 함정
```

## ⑩ iOS 제약과 브라우저 호환성 확인법

```
iOS(아이폰)에서 PWA가 안드로이드와 뭐가 다른지 정리해줘.

- iOS 사파리에서 되는 것 / 안 되는 것 목록
  (홈 화면 추가, 서비스 워커, 푸시 알림, Web Share Target, 설치 배너 등)
- Web Share Target이 iOS에서 지원되지 않는다고 들었는데 맞는지,
  2026년 현재 기준으로 바뀐 게 있는지 확인해줘
- iOS에서 홈 화면에 추가한 웹 앱의 데이터(localStorage)가
  일정 기간 안 쓰면 지워진다는 게 사실인지, 조건이 뭔지,
  navigator.storage.persist()로 막을 수 있는지
- 안드로이드에만 되는 기능을 넣었을 때, iOS 사용자에게
  대체 경로를 주는 설계 패턴 (progressive enhancement)

그리고 이런 "이 브라우저에서 되나?"를 내가 직접 확인하는 방법을 알려줘.
caniuse.com, MDN의 호환성 표를 어떻게 읽는지, 각 표기(부분 지원, 플래그 필요 등)가
무슨 뜻인지 실제 예시로 보여줘.
```

## ⑪ 마지막 — 이해 점검

```
지금까지 설명해준 것들(PWA, manifest, Web Share Target, GET/POST,
SPA 라우팅과 폴백, 서비스 워커, HTTPS, 아이콘, iOS 제약)을 바탕으로
내 이해도를 점검해줘.

1. 객관식이 아닌 서술형 질문 7개를 한 번에 하나씩 던져줘.
   내가 답하면 채점하고 틀린 부분을 고쳐준 다음 다음 문제로 넘어가줘.
2. 특히 "왜 그렇게 되는가"를 묻는 질문으로 해줘. 암기 말고.
3. 다 끝나면 내가 약한 주제를 짚어주고, 그 주제만 다시 공부할
   순서를 만들어줘.

한 번에 다 보여주지 말고 하나씩.
```
