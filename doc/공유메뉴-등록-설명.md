# 공유 메뉴에 북칸쇼 띄우기 — 쉬운 설명

작성일: 2026-10-08
대상: `public/manifest.webmanifest`, `src/pages/Share.jsx`, `src/lib/shareTarget.js`, `public/sw.js`

이 문서는 "공유 메뉴에 앱 띄우기"로 바뀐 것이 **무엇이고 왜 그렇게 했는지**를
용어를 풀어서 적은 것이다. 코드를 읽기 전에 이것부터 보면 된다.

---

## 1. 뭘 고치려는 건가

지금 문구 하나를 저장하려면 손이 세 번 간다.

```
밀리의 서재에서 문구 선택 → 복사
→ 홈 화면으로 나가서 북칸쇼 열기
→ 입력칸 길게 눌러 붙여넣기 → 저장
```

바꾼 뒤에는 두 번이면 끝난다.

```
밀리의 서재에서 문구 선택 → 공유 → 목록에서 "북칸쇼" 선택
→ (문구가 이미 채워진 화면이 뜬다) → 저장
```

차이는 **"앱을 내가 찾아서 여는 것"이 "안드로이드가 대신 열어 주는 것"으로 바뀐 것**이다.

---

## 2. "공유 메뉴에 뜬다"는 게 기술적으로 무슨 일인가

안드로이드에서 공유 버튼을 누르면 뜨는 그 목록(카톡, 메모, 드라이브…)은
**안드로이드가 관리하는 목록**이다. 앱이 설치될 때 "나는 글자를 받을 수 있다"고
등록해 두면 저 목록에 끼워 준다.

웹 앱도 같은 등록을 할 수 있다. 등록서에 해당하는 파일이 **manifest**다.

> **manifest(매니페스트)란?**
> 웹사이트가 "나는 그냥 사이트가 아니라 앱이다"라고 신고하는 파일이다.
> 앱 이름, 아이콘, 배경색 같은 걸 적는다. 여기 **`share_target`** 항목을 넣으면
> "공유 목록에도 넣어 달라"는 신고가 된다.

우리가 넣은 신고 내용은 `public/manifest.webmanifest`에 있다.

```json
"share_target": {
  "action": "/share",
  "method": "GET",
  "params": { "title": "title", "text": "text", "url": "url" }
}
```

읽으면 이렇다.

- `action: "/share"` — 누가 나한테 공유하면 **`/share` 주소를 열어 달라**
- `params` — 공유된 내용을 `title`, `text`, `url`이라는 **이름표를 달아서** 달라

---

## 3. GET으로 한 이유

공유받은 글자를 앱에 전달하는 방법이 두 가지다.

| | GET (우리가 고른 것) | POST |
|---|---|---|
| 전달 방식 | 주소 뒤에 글자를 붙여서 | 눈에 안 보이게 봉투로 |
| 받는 쪽 | 앱이 **주소만 읽으면 끝** | **서비스 워커가 봉투를 뜯어야** 함 |
| 사진 전달 | 못 함 | 할 수 있음 |

밀리의 서재가 보내는 건 글자뿐이라 사진을 받을 일이 없다.
그래서 더 간단한 GET으로 했다. 공유를 누르면 안드로이드가 실제로 여는 주소는 이런 모양이다.

```
/share?text=문구%20한%20줄%0A<어떤%20책>,%20저자%20-%20밀리의%20서재
```

`?` 뒤가 공유받은 내용이다. 앱은 이 주소를 읽기만 하면 된다.

---

## 4. 받은 글자가 저장되기까지

```
안드로이드가 /share?text=... 를 연다
        │
        ▼
src/pages/Share.jsx        ← 주소에서 title·text·url을 꺼낸다
        │
        ▼
src/lib/shareTarget.js     ← 셋을 다시 한 덩어리 글자로 합친다
        │
        ▼
src/lib/parseShare.js      ← 원래 쓰던 그 함수. 제목·저자·본문으로 쪼갠다
        │
        ▼
src/components/PasteBox.jsx ← 쪼갠 내용이 이미 채워진 화면이 뜬다 → 저장
```

**핵심은 맨 아래 두 칸이 원래 쓰던 것 그대로라는 점이다.**
붙여넣기로 저장하던 길에 "공유로 들어오는 입구"만 하나 더 뚫었다.
그래서 `parseShare`도, 저장 로직도 손대지 않았다.

### shareTarget.js가 하는 일이 왜 따로 필요한가

앱마다 글자를 어디에 담아 보낼지가 제멋대로다.

- 어떤 앱은 `text`에 전부 담는다
- 어떤 앱은 제목은 `title`, 본문은 `text`로 나눈다
- 어떤 앱은 주소를 `url`에 따로 담고, 어떤 앱은 `text` 안에 이미 섞어 보낸다

이걸 그대로 두면 `parseShare`가 "마지막 줄이 서지 정보"라는 규칙을 못 쓴다.
그래서 **먼저 하나로 합쳐 놓는 역할**만 떼어 `shareTarget.js`에 뒀다.
주소가 본문에 이미 들어 있으면 두 번 붙이지 않는 것도 여기서 한다.

---

## 5. 서비스 워커는 왜 넣었나

공유 목록에 뜨려면 **앱이 설치돼 있어야** 한다. 그냥 북마크는 안 되고,
안드로이드가 "이건 앱이다"라고 인정해야 한다.

크롬이 인정하는 조건이 세 개다.

1. HTTPS로 열릴 것
2. manifest에 이름과 아이콘이 있을 것
3. **서비스 워커가 등록돼 있을 것**

3번 때문에 `public/sw.js`를 넣었다.

> **서비스 워커란?**
> 앱과 인터넷 사이에 앉아 있는 작은 중계원이다. 페이지가 뭔가 받아 올 때
> 먼저 가로채서 "이건 내가 저장해 둔 게 있으니 그걸 주자" 같은 판단을 한다.
> 이게 있어야 비행기 모드에서도 앱이 열린다.

우리 중계원은 아주 단순하다.

- 화면을 열 때: **인터넷 먼저** 시도하고, 안 되면 저장해 둔 껍데기를 준다
- 그림·CSS 같은 건: 저장해 둔 게 있으면 그걸 주고, 없으면 받아서 저장해 둔다

개발 중에는 이 중계원이 옛날 파일을 계속 쥐고 있어서 방해가 된다.
그래서 **빌드본에서만 켜지게** 했다(`src/main.jsx`).
`npm run dev`로 띄운 개발 서버에는 끼어들지 않는다.

---

## 6. 아이콘

설치형 앱이 되려면 홈 화면에 놓일 아이콘이 필요하다. 원래 있던 `favicon.svg`는
Vite 템플릿에 딸려 온 보라색 로고라 이 앱과 아무 상관이 없었다.
그래서 종이·먹색에 맞춘 펼친 책 모양으로 새로 그렸다.

| 파일 | 쓰임 |
|---|---|
| `app-icon.svg` | 브라우저 탭 |
| `icon-192.png` | 홈 화면, 공유 목록 |
| `icon-512.png` | 설치 화면 |
| `icon-maskable-512.png` | 안드로이드가 아이콘을 원·사각으로 잘라낼 때 |

마지막 것만 따로 있는 이유: 안드로이드는 기기마다 아이콘을 동그라미나
둥근 사각형으로 **잘라낸다**. 잘려도 되게 가장자리를 비워 둔 판본이 필요하다.

## 7. 배포할 때 걸릴 두 가지

### (1) SPA 폴백 — 이게 없으면 공유해도 "페이지를 찾을 수 없음"이 뜬다

우리 앱은 화면이 여러 개로 보이지만 **실제 파일은 `index.html` 하나뿐이다.**
`/book/3`이든 `/share`든 같은 파일을 받아서 자바스크립트가 화면만 바꿔 그린다.

그런데 서버는 그걸 모른다. 브라우저가 `/share`를 달라고 하면
서버는 `share`라는 폴더를 찾다가 없으니 **404를 돌려준다.**

```
브라우저: /share 주세요
서버:     그런 폴더 없는데요? → 404       ← 이러면 끝
```

그래서 서버에 "**모르는 주소는 전부 `index.html`을 줘라**"라고 적어 둬야 한다.
이걸 SPA 폴백이라고 한다. 호스트마다 적는 곳이 다르다.

```
Netlify  → public/_redirects 파일에:  /*  /index.html  200
Vercel   → vercel.json 의 rewrites
nginx    → try_files $uri $uri/ /index.html;
```

지금까지 이게 없어도 괜찮았던 건, 늘 첫 화면(`/`)으로 들어가서
앱 안에서만 이동했기 때문이다. 공유 메뉴는 **`/share`로 바로 들어오기 때문에**
여기서 처음 문제가 된다.

### (2) 한 번은 "홈 화면에 추가"를 해야 한다

HTTPS 주소로 앱을 열고 크롬 메뉴에서 **홈 화면에 추가**를 눌러야
안드로이드가 앱으로 등록하고, 그때부터 공유 목록에 "북칸쇼"가 뜬다.
설치 전에는 아무리 공유해도 목록에 없다.

---

## 8. 아이폰은 왜 안 되나

iOS 사파리는 **웹 앱을 공유 목록에 등록하는 기능 자체를 아직 지원하지 않는다.**
우리가 뭘 더 해서 되는 문제가 아니다.

아이폰에서는 이렇게 동작한다.

- 홈 화면에 추가해서 앱처럼 쓰는 것: **된다**
- 공유 메뉴에 "북칸쇼"가 뜨는 것: **안 된다**
- `/share` 주소로 들어가는 것: 된다. 단, 빈 붙여넣기 화면이 뜬다

그래서 `Share.jsx`가 공유로 들어왔는지 아닌지를 보고 안내 문구를 바꾼다.
아이폰 사용자에겐 "공유 메뉴를 쓸 수 없으면 여기에 직접 붙여넣으세요"가 뜬다.

## 9. 확인하는 법

### 컴퓨터에서 (공유 없이 받는 쪽만 확인)

```bash
npm run build && npm run preview
```

그다음 주소창에 직접 쳐 넣는다.

```
http://localhost:4173/share?text=문구 한 줄%0A<어떤 책>, 저자 - 밀리의 서재
```

제목 `어떤 책`, 저자 `저자`, 본문 `문구 한 줄`이 채워진 화면이 뜨면 받는 쪽은 정상이다.

### 안드로이드 폰에서 (진짜 확인)

1. 배포한 **HTTPS** 주소를 크롬으로 연다
2. 크롬 메뉴 → **홈 화면에 추가**
3. 밀리의 서재에서 문구를 고르고 **공유**를 누른다
4. 목록에 **북칸쇼**가 보이면 성공

안 보일 때 볼 것:
- HTTP로 열지 않았는지 (HTTPS여야 한다)
- 홈 화면 추가를 실제로 했는지
- 크롬 주소창에 `chrome://inspect/#service-workers` — 서비스 워커가 등록됐는지
- 배포 서버에서 `/manifest.webmanifest`를 직접 열어 내용이 나오는지

## 10. 건드린 파일

| 파일 | 한 일 |
|---|---|
| `public/manifest.webmanifest` | **새로 만듦.** 앱 신고서 + 공유 목록 등록 |
| `public/sw.js` | **새로 만듦.** 설치 조건을 채우는 중계원, 오프라인 |
| `public/app-icon.svg`, `icon-*.png` | **새로 만듦.** 앱 아이콘 |
| `src/lib/shareTarget.js` | **새로 만듦.** 공유받은 조각들을 한 덩어리로 |
| `src/pages/Share.jsx` | **새로 만듦.** `/share` 화면 |
| `index.html` | manifest·아이콘 연결, 테마색 |
| `src/main.jsx` | 서비스 워커 등록(빌드본에서만) |
| `src/App.jsx` | `/share` 경로 추가 |
| `src/components/PasteBox.jsx` | 내용을 미리 채워 열 수 있게 `initialRaw` 추가 |

`parseShare.js`와 저장 로직은 **손대지 않았다.**

---

## 11. 한 줄 요약

> manifest에 "나는 글자를 받을 수 있다"고 신고해 두면, 안드로이드가 공유 목록에
> 북칸쇼를 끼워 준다. 고르면 `/share?text=...` 주소로 앱을 열어 주고,
> 앱은 그 주소를 읽어 원래 쓰던 붙여넣기 화면에 미리 채워 넣는다.
> 설치형 앱이어야 하므로 서비스 워커와 아이콘이 필요하고,
> 서버에는 모르는 주소를 `index.html`로 보내는 설정이 있어야 한다.
