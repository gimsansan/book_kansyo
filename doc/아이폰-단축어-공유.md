# 아이폰에서 공유 메뉴로 저장하기 — iOS 단축어

작성일: 2026-10-08
대상: iOS 단축어(Shortcuts) 앱. **코드 변경 없음**
관련: `doc/공유메뉴-등록-설명.md` (안드로이드 쪽), `수정해나갈것.md` 4번

> **2026-10-08 기준: 지금은 쓸 일이 없다.**
> 아이폰을 쓰지 않기로 확인됐다(안드로이드 폰 + 맥/윈도 크롬).
> 아이폰을 쓰게 되거나 아이폰 쓰는 사람에게 앱을 줄 때를 위해 남겨 둔다.
> 2장의 저장소 분리 문제는 그때 반드시 먼저 읽는다.

---

## 1. 뭘 만드는 건가

안드로이드는 manifest의 `share_target` 덕분에 공유 메뉴에 북칸쇼가 뜬다.
**iOS 사파리는 이 기능을 지원하지 않는다.** 아이폰에서는 여전히 3단계다.

```
밀리의 서재에서 문구 선택 → 복사 → 앱 열기 → 붙여넣기 → 저장
```

iOS 단축어가 `share_target`의 **대역**을 설 수 있다.
단축어도 공유 시트에 등장할 수 있기 때문이다.

```
밀리의 서재에서 문구 선택 → 공유 → "북칸쇼" 단축어 → (채워진 화면) → 저장
```

단축어가 하는 일은 딱 하나다. **받은 글자를 주소에 실어 `/share`를 여는 것.**
앱은 그 주소를 읽는 입구(`src/pages/Share.jsx`)를 이미 갖고 있으므로,
**앱 코드는 한 줄도 바뀌지 않는다.**

```
안드로이드:  밀리 → [안드로이드 OS] → /share?text=... → 앱
아이폰:      밀리 → [단축어]        → /share?text=... → 앱
                     ↑ 이 칸만 사람이 만든다
```

## 2. 먼저 결정할 것 — 사파리냐 홈 화면 앱이냐 ⚠️

**이 문서에서 제일 중요한 부분이다. 만들기 전에 읽는다.**

iOS는 홈 화면에 추가한 웹 앱과 사파리를 **저장소를 따로 쓴다.**
같은 주소인데도 담긴 데이터가 다르다.

```
사파리에서 연 북칸쇼         홈 화면 아이콘으로 연 북칸쇼
   localStorage A      ≠        localStorage B
   (문구 12개)                   (문구 30개)
```

단축어가 URL을 열면 **사파리가 열린다.** 홈 화면 앱으로는 들어가지 못한다.
안드로이드처럼 설치된 앱으로 링크를 넘겨주는 길이 iOS에는 없다.

그래서 아이폰에서는 **한쪽만 골라서 일관되게 써야 한다.**

| 선택 | 장점 | 단점 |
|---|---|---|
| **사파리만 쓴다** (단축어 쓰려면 이쪽) | 단축어 경로가 그대로 동작. 데이터가 한곳에 모임 | 홈 화면 앱의 전체화면 느낌을 포기 |
| **홈 화면 앱만 쓴다** | 앱처럼 보임. 저장소가 덜 지워짐 | 단축어가 무용지물. 계속 3단계 |

> **섞어 쓰면 안 된다.** 어제 단축어로 저장한 문구가 오늘 홈 화면 앱에서 안 보인다.
> 잃어버린 게 아니라 다른 칸에 들어가 있는 것인데, 알아채기가 매우 어렵다.

이 갈림길은 **서버를 두면 사라지지만, 서버는 안 쓰기로 했다**(`doc/데이터-보관-결정.md`).
그러니 아이폰에서는 한쪽을 고르고 계속 그쪽만 쓴다.

**이미 홈 화면 앱에 문구를 저장해 뒀다면**, 단축어로 넘어가기 전에
홈 화면 앱에서 **JSON 내보내기 → 사파리에서 가져오기**를 한 번 해서 옮긴다.

## 3. 블록 순서

단축어 4칸이면 끝난다.

```
┌─────────────────────────────────────────────┐
│ ① 공유 시트에서 받기        (단축어 설정)    │
│    받는 형식: 텍스트                          │
└───────────────┬─────────────────────────────┘
                │ "문구 한 줄\n<어떤 책>, 저자 - 밀리의 서재"
                ▼
┌─────────────────────────────────────────────┐
│ ② URL 인코딩                                 │
│    입력: 단축어 입력                          │
└───────────────┬─────────────────────────────┘
                │ "%EB%AC%B8%EA%B5%AC%20..." (안전한 글자만 남음)
                ▼
┌─────────────────────────────────────────────┐
│ ③ 텍스트                                     │
│    https://배포주소/share?text=[URL 인코딩됨] │
└───────────────┬─────────────────────────────┘
                │ 완성된 주소
                ▼
┌─────────────────────────────────────────────┐
│ ④ URL 열기                                   │
└─────────────────────────────────────────────┘
                 → 사파리가 /share를 열고,
                   앱이 주소에서 text를 꺼내 채운다
```

## 4. ②번이 왜 필요한가 — URL 인코딩

②를 빼면 **거의 반드시 깨진다.** 이유를 알아야 디버깅이 된다.

주소(URL)에 그냥 넣으면 안 되는 글자들이 있다. 주소 문법에서 뜻을 가진 글자들이다.

| 글자 | 주소에서의 뜻 | 인코딩하면 |
|---|---|---|
| 공백 | 주소의 끝 | `%20` |
| 줄바꿈 | 주소에 못 들어감 | `%0A` |
| `&` | 다음 파라미터 시작 | `%26` |
| `#` | 페이지 안 위치 표시 | `%23` |
| `?` | 쿼리 시작 | `%3F` |
| `+` | (문맥에 따라) 공백 | `%2B` |
| 한글 | 원래 못 들어감 | `%EB%AC%B8` 식 |

밀리의 서재 공유 문구에는 **공백도, 줄바꿈도, 한글도 전부 들어 있다.**

특히 **줄바꿈**이 치명적이다. `parseShare`는 "마지막 줄이 서지 정보"라는 규칙으로
제목·저자를 찾는데, 줄바꿈이 사라지면 전체가 한 줄이 되어 **제목을 못 찾는다.**
화면에는 "형식을 못 찾았습니다"가 뜨고 제목을 직접 쳐야 한다.

`#`은 더 조용히 깨진다. `#` 뒤는 서버로 전송되지 않으므로 **문구 뒷부분이 통째로 사라진다.**

> **인코딩이란?** 특별한 뜻을 가진 글자를 "이건 그냥 글자다"라고 표시해 두는 것이다.
> `%` 뒤에 그 글자의 번호를 붙인다. 받는 쪽(브라우저)이 자동으로 되돌려 주므로,
> 앱 코드에서는 원래 글자 그대로 읽힌다. `Share.jsx`에서 디코딩 코드를 안 쓴 이유다.

### 인코딩 안 했을 때 실제로 생기는 일

```
원본:   문구 한 줄
        <어떤 책>, 저자 - 밀리의 서재

인코딩 X → https://.../share?text=문구 한 줄
                                    ↑ 여기서 주소가 끊김
           결과: "문구" 만 전달되거나 주소 자체가 실패

인코딩 O → https://.../share?text=%EB%AC%B8%EA%B5%AC%20%ED%95%9C%20%EC%A4%84%0A%3C...
           결과: 줄바꿈까지 그대로 전달 → 제목·저자 자동 인식
```

## 5. 만드는 법

> 배포 주소를 `https://booknote.example.com` 이라고 가정한다.
> **실제 배포 주소로 바꿔서** 만든다. 끝에 `/`는 붙이지 않는다.

### 1) 단축어 새로 만들기

1. **단축어** 앱 → 오른쪽 위 **+**
2. 이름을 **북칸쇼**로 바꾼다 (공유 시트에 이 이름이 뜬다)

### 2) ② URL 인코딩 블록

1. 검색창에 **`URL 인코딩`** 입력 → 나오는 동작 추가
   (영문판 이름은 `URL Encode`. 모드가 **인코딩**인지 확인한다. 디코딩 아님)
2. 입력 자리를 탭 → **단축어 입력** 선택
   - 이 항목이 안 보이면, 아직 공유 시트 설정을 안 해서다. 5번 단계를 먼저 하고 돌아온다

### 3) ③ 텍스트 블록

1. **`텍스트`** 동작 추가
2. 내용에 주소를 친다. **중간에 ②의 결과를 끼워 넣는다.**

```
https://booknote.example.com/share?text=
```

까지 직접 치고, 이어서 **변수 선택 → URL 인코딩됨 텍스트**를 넣는다.
완성 모양:

```
https://booknote.example.com/share?text=[URL 인코딩됨 텍스트]
```

> `[...]`는 직접 치는 글자가 아니라 **파란 알약 모양 변수**다. 손으로 치면 안 된다.

### 4) ④ URL 열기 블록

1. **`URL 열기`** 동작 추가 (영문 `Open URLs`)
2. 입력이 ③의 **텍스트**로 잡혀 있는지 확인한다

### 5) ① 공유 시트에 띄우기 — 가장 많이 빠뜨리는 단계

1. 단축어 편집 화면 위쪽의 **ⓘ(정보)** 또는 **세부사항** 탭
2. **공유 시트에 표시** 를 켠다
3. 바로 아래 **공유 시트 유형**을 탭 → **텍스트**만 남기고 나머지는 끈다
   - URL도 켜 두면 밀리가 아닌 웹페이지를 공유했을 때도 뜬다. 거슬리면 텍스트만 둔다
4. 완료 → 저장

### 6) 아이콘 (선택)

이름 옆 아이콘을 탭해 색과 기호를 고른다. 공유 시트에서 눈에 잘 띈다.

## 6. 확인하는 법

### 단축어만 먼저 (밀리 없이)

1. 메모 앱에 아래를 **두 줄로** 치고 전체 선택 → 공유
```
문구 한 줄
<어떤 책>, 저자 - 밀리의 서재
```
2. 공유 시트에서 **북칸쇼** 선택
3. 사파리가 열리고 **제목 `어떤 책` / 저자 `저자` / 본문 `문구 한 줄`** 이 채워져 있으면 성공

### 실제 사용

밀리의 서재에서 문구 선택 → 공유 → 북칸쇼 → 저장

## 7. 안 될 때

| 증상 | 원인 | 조치 |
|---|---|---|
| 공유 시트에 북칸쇼가 없다 | "공유 시트에 표시"가 꺼져 있음 | 5-5 단계 |
| 공유 시트 맨 아래에만 작게 보인다 | 자주 쓰는 목록에 없음 | 공유 시트 맨 아래 **동작 편집**에서 위로 올림 |
| "형식을 못 찾았습니다"가 뜬다 | **줄바꿈이 깨짐.** 인코딩 블록 빠졌거나 순서가 틀림 | ②가 ③보다 **위**에 있는지, ③에 들어간 변수가 **인코딩됨** 변수인지 확인 |
| 문구 뒷부분이 잘림 | 원문에 `#`이나 `&`가 있는데 인코딩 안 됨 | 위와 같음 |
| 빈 화면이 뜬다 (주소는 맞음) | 배포 서버에 **SPA 폴백**이 없어 `/share`가 404 | `doc/공유메뉴-등록-설명.md` 7장 |
| 저장은 되는데 홈 화면 앱에서 안 보인다 | **2장의 저장소 분리 문제** | 한쪽만 쓰기로 정하고, JSON으로 옮김 |
| 사파리가 아니라 다른 브라우저가 열린다 | 기본 브라우저 설정 | 설정 → 앱 → 기본 브라우저 |

## 8. 안드로이드와 뭐가 다른가

| | 안드로이드 | 아이폰(단축어) |
|---|---|---|
| 등록 주체 | manifest의 `share_target` | 사람이 만든 단축어 |
| 설치 | 홈 화면에 추가 한 번 | 단축어 직접 제작 |
| 인코딩 | 안드로이드가 알아서 | **②번 블록으로 직접** |
| 열리는 곳 | 설치된 PWA | **사파리** |
| 저장소 | PWA 하나 | 사파리와 홈 화면 앱이 **분리** |
| 다른 기기로 옮기기 | 주소만 알면 됨 | 단축어를 공유하거나 다시 만듦 |
| 앱 코드 | `/share` 입구 (이미 있음) | **같은 입구를 그대로 씀** |

마지막 줄이 핵심이다. 두 경로가 **같은 문 하나**로 들어온다.
`/share?text=` 입구를 바꾸면 양쪽이 같이 영향을 받으므로, 손댈 때 둘 다 생각한다.

---

## 9. 한 줄 요약

> iOS는 웹 앱을 공유 메뉴에 등록하지 못한다. 그 자리를 단축어가 대신한다.
> 단축어는 받은 글자를 **URL 인코딩해서** `/share?text=`에 실어 열기만 하면 되고,
> 앱 코드는 바뀌지 않는다. 대신 사파리가 열리므로, **사파리와 홈 화면 앱 중
> 한쪽만 일관되게 쓴다.** 서버를 안 쓰기로 했으므로 이 제약은 그대로 남는다.
